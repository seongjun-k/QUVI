# VLA(SmolVLA 2캠) 에피소드 재수집 가이드라인

작성 2026-11-02. 기존 데이터셋 `Task_1_pick_quvi_MCAP_lerobot_v30`(218에피소드, 15fps)과
QUVI 실기 추론 트레이스(`data/act_traces/`, 마지막 2026-09-20)를 비교 분석한 결과를 바탕으로 정리했다.
"실측"은 데이터에서 직접 계산한 값이고, "추정"은 원인 가설이다.

## 0. 왜 다시 정하나 — 기존 데이터에서 찾은 문제

실기 증상: 못 잡음, 엉뚱한 곳으로 감, 발산, 떨림.

| # | 문제 | 실측 근거 | 영향(추정) |
|---|---|---|---|
| 1 | **추론 시작 자세가 학습 시작 자세와 다르다** | QUVI 홈(`POSE_HOME`) raw `[2037,1114,2771,3257,2016,2500]` vs 학습 에피소드 시작 평균 raw `[2069,1003,2922,3036,2040,2489]`. 차이 shoulder_lift +9.8°, elbow −13.3°, wrist_flex +19.4°. 실기 트레이스 시작값 기준 표준점수 elbow −3.1σ, wrist +3.0σ이고, wrist는 학습 데이터 전체 최댓값(1.835 rad)보다 크다(1.855 rad) | 첫 스텝부터 학습 분포 밖 → 엉뚱한 액션 → 오차 누적으로 발산 |
| 2 | 시작 자세가 세션마다 다르다 | 시작 shoulder_lift 표준편차 0.13 rad(7.4°). 에피소드 0~109 평균 −1.695 rad, 110 이후 평균 −1.509 rad | 정책이 "어디서 시작하든"을 배우느라 데이터가 분산됨 |
| 3 | 시연 속도가 두 종류로 섞였다 | 에피소드 길이 중앙값이 앞 120개는 77~86프레임, 뒤 98개는 52~55프레임 | 빠른/느린 동작 평균화 → 어중간한 궤적, 떨림 |
| 4 | 정책 실행 시간과 시연 길이가 다르다 | 시연 중앙값 4.9초(p90 6.1초, 최대 8.4초). QUVI는 `ACT_GRASP_DURATION = 7.0`초 고정 실행 | 시연이 끝난 뒤 1~2초는 학습에 없는 구간 → 끝에서 흔들림·발산 |
| 5 | 시작 대기 프레임이 길다 | 첫 움직임까지 중앙값 12프레임(0.8초), 최대 30프레임(2초) | "가만히 있기"를 학습 → 머뭇거림 |
| 6 | 물체 위치가 넓게 흩어졌다 | 파지 순간 shoulder_pan 범위 ±0.55 rad(±32°), wrist_roll 표준편차 0.37 rad(21°) | 위치당 시연 수가 적음. 실제 출력물은 거의 같은 자리에 나오는데 데이터는 넓게 퍼짐 |
| 7 | 탑뷰 카메라 설정이 수집과 추론에서 다르다 | 10-06(f8e1fe2)부터 QUVI 추론은 탑뷰를 수동 노출 80, brightness 0으로 고정. 수집은 open_manipulator 컨테이너의 usb_cam이 띄우며, 같은 커밋 메시지대로 usb_cam은 노출 설정이 무시되고 자동노출+brightness 50(베드 반사 포화 14%) | 학습 영상과 추론 영상의 밝기가 다름. 10-06 이후 추론에서 해당 |

문제가 아니었던 것: 지시문은 1종(`Pick up the printed part from the bed.`, tasks=1), 카메라 키는 `rgb.camera1`(사이드)·`rgb.camera3`(탑뷰), 그리퍼 시작값(raw 약 2489)은 QUVI 개방값 2500과 일치, 시연 액션 반전율은 평균 7.5%로 매끄러움.

**가장 유력한 원인은 1번이다.** 그러나 아래 "1단계 영점 확인"을 하기 전에는 "자세가 다르다"인지 "같은 자세인데 단위 변환 영점이 다르다"인지 구분할 수 없다. 둘은 대책이 다르다.

## 1단계 — 수집 시작 전 확인 (반드시, 1회)

### 1-1. 하드웨어 동결
로봇 형상, 턴테이블, 베드 높이, **카메라 2대의 위치·각도**가 최종 상태로 고정된 뒤에 수집한다.
수집 뒤에 하나라도 바뀌면 그 데이터는 다시 찍어야 한다. 카메라 마운트는 나사 고정 후 위치를 사진으로 남긴다.

### 1-2. 영점 확인 (원인 1번 판별)
1. QUVI로 팔을 홈 자세(`POSE_HOME`)에 둔다.
2. Cyclo(open_manipulator) 쪽에서 같은 자세의 `/joint_states` 라디안 값을 읽는다(읽기만).
3. 아래 기대값과 비교한다. 기대값은 QUVI 변환식 `rad = (raw − 2048) × 2π / 4096`으로 계산했다.

| 관절 | joint1 | joint2 | joint3 | joint4 | joint5 | gripper_joint_1 |
|---|---|---|---|---|---|---|
| 기대 rad | −0.017 | −1.433 | 1.109 | 1.855 | −0.049 | 0.693 |

- **모든 관절이 ±0.02 rad 안**이면 영점은 같다. 원인은 시작 자세 차이이고, 2단계 규칙(홈에서 시작)으로 해결된다.
- **차이가 크면** 변환 영점이 다르다. 데이터를 다시 찍어도 같은 문제가 반복되므로, 수집 전에 QUVI 쪽 변환을 고쳐야 한다(로봇 동작 변경이라 별도 승인 필요). 이 경우 측정값을 기록해서 공유한다.

### 1-3. 카메라 설정 통일 (원인 7번)
수집 세션 시작 직전과 추론 직전에 각각 두 카메라의 설정을 읽어 기록하고, 값이 같아야 한다.

```bash
# 호스트에서, 장치 경로는 HMI 장치 설정에서 쓰는 노드로
v4l2-ctl -d <탑뷰 장치> --get-ctrl auto_exposure,exposure_time_absolute,brightness
v4l2-ctl -d <사이드 장치> --get-ctrl auto_exposure,exposure_time_absolute,brightness
```

수집할 때도 탑뷰는 QUVI 추론과 같은 값으로 맞춘다: `--set-ctrl auto_exposure=1,exposure_time_absolute=80,brightness=0`.
(usb_cam이 재시작되면 값이 되돌아갈 수 있으므로 세션마다 다시 확인한다.)
조명(LED 켜짐 여부, 실내등, 창문 블라인드)도 추론 때와 같은 상태로 둔다.

## 2단계 — 에피소드 1개를 찍는 규칙

| 항목 | 규칙 | 기존 데이터 실측 |
|---|---|---|
| 시작 자세 | **매 에피소드 QUVI 홈 자세에서 시작.** 팔로워가 홈 기준 각 관절 ±20 raw(약 ±2°) 안에 들어온 것을 확인한 뒤 녹화 시작. 리더 팔에 홈 위치 표시(지그·테이프)를 만들어 둔다 | 표준편차 최대 7.4°, 세션 간 차이 있음 |
| 시작 대기 | 녹화 시작 후 **0.5초(8프레임) 안에** 움직이기 시작 | 중앙값 0.8초, 최대 2초 |
| 속도 | 한 명이 찍는 것을 권장. 목표 **4~5초**, 3초 미만이나 7초 초과는 버리고 다시 찍기 | 3.5초 / 5.5초 두 속도가 섞임 |
| 동작 순서 | 홈 → 물체 위로 접근 → 내려가서 파지(그리퍼 끝까지 닫기) → 들어 올려 **홈 자세로 복귀** → 끝 | 기존과 같음(끝 자세 = 홈 근처, 그리퍼 닫힘 218/218) |
| 끝 | 홈 자세 복귀 후 **1초 정지**하고 녹화 종료. 매번 같은 길이로 | 끝 정지 중앙값 6프레임, 최대 38프레임 |
| 실패한 시연 | 놓침, 재시도, 부딪힘이 있으면 저장하지 않고 다시 찍기 | — |
| 지시문 | `Pick up the printed part from the bed.` 그대로(마침표 포함). 수집 화면 입력값을 매 세션 첫 에피소드 전에 대조 | 1종, 정상 |

끝의 "1초 정지"는 권장안이다. 정책이 시연 뒤 구간에서 가만히 있도록 가르치려는 목적이다. 실행 시간(`ACT_GRASP_DURATION`)을 시연 길이에 맞게 줄이는 방법도 있는데, 이는 로봇 동작 변경이라 별도로 정한다.

## 3단계 — 물체 배치 계획

- **실제 출력물이 나오는 자리를 중심으로 찍는다.** 프린터가 출력하는 위치(베드 중앙 등)를 기준점으로 표시한다.
- 권장 배분: 70%는 기준점 ±2cm 안에서 작게 흔들어 배치, 30%는 그보다 넓게(실제로 나올 수 있는 범위까지만).
- 방향(물체 회전)도 실제 출력 방향 위주로, 일부만 돌려서 찍는다. 기존 데이터는 wrist_roll이 21°만큼 흩어져 있었다.
- **품종별 개수를 기록한다.** 기존 데이터에는 에피소드별 품종 정보가 없어서 분포를 알 수 없었다. 수집 시트에 `에피소드 번호 / 품종 / 위치 칸 / 방향 / 성공 여부`를 적는다.

## 4단계 — 개수와 학습

- 검증된 레시피: 120에피소드(3품종) / batch 32 / 약 20epoch(6000 step) → Cyclo 경로 실기에서 3품종 파지 성공(2026-09-07).
- 목표: **품종당 40개 이상, 합계 120개 이상.** 개수를 늘리는 것보다 1·2단계 규칙을 지키는 게 우선이다.
- 변환 후 tasks.parquet가 1행인지 확인한다(마침표 차이로 tasks=2가 된 사고 이력).

## 5단계 — 세션 끝날 때 품질 확인

변환된 데이터셋에서 아래를 확인한다. 기존 데이터 분석에 쓴 계산과 같다.

1. 에피소드 첫 프레임 state 평균이 1-2의 기대값(또는 실측값)과 각 관절 ±0.03 rad 안
2. 첫 프레임 state 표준편차가 각 관절 0.03 rad 이하
3. 길이 분포가 60~75프레임(4~5초) 안에 모여 있음
4. 첫 움직임까지 8프레임 이하
5. tasks = 1

벗어나는 에피소드는 지우고 다시 찍는다.

## 아직 확인하지 않은 것

- 1-2 영점 확인 결과(하드웨어 필요).
- 기존 모델의 개루프 평가: 데이터셋 프레임을 모델에 넣어 녹화 액션과 비교하는 시험. 이 시험으로 "모델 자체가 시연을 재현하지 못하는지"를 판별할 수 있다. 새 데이터로 학습한 뒤에도 같은 방법으로 검증한다.
- 사이드캠 설정과 조명이 기존 수집 때 어땠는지(기록 없음).
